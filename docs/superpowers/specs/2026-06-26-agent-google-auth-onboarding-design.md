# Agent Google Auth + Onboarding — Design Spec (Agent Campaign, Sub-project 4 of 5)

- **Date:** 2026-06-26
- **Status:** Approved — proceeding to plan
- **Repos:** Backend `RenoXpert-Backend` (deploys from `production`, PR-protected) + Frontend `RenoXpert-Frontend-v2.1` (deploys from `production`, merge+push)
- **Part of:** Agent Campaign (SP1 ✅, SP2 ✅, SP3 ✅; SP5 agent portal pending). Agents = `users.type='agent'`.

## 1. Goal

Let agents sign in with Google, auto-create an agent account on first login, complete a simple onboarding (phone + confirm name + agree T&C), and reach a gated agent area. The **portal content (campaign list + referral links) is SP5** — SP4 ends at a gated placeholder agent home.

## 2. Decisions (locked)

- **Verify:** FE `@react-oauth/google` button → sends the Google **ID token** → BE verifies it via **Google's tokeninfo endpoint over Guzzle** (no new backend dependency), checking `aud === GOOGLE_CLIENT_ID` and `email_verified`.
- **Signup:** **open self-signup**, active immediately (first Google login → `type='agent'`, `status='active'`).
- **Onboarding:** phone (`country_code` + `phone_no`, required) + editable name (prefilled from Google) + a **T&C agreement** checkbox; marked complete via `users.onboarded_at`.
- **Email clash:** if the Google email already belongs to a **non-agent** user → **reject** (422). type='agent' → log in. New → create.

## 3. Scope

- **Backend:** `users.onboarded_at` column; `services.google.client_id` config; `AgentAuthController` with `googleLogin` + `onboarding`; routes.
- **Frontend:** `@react-oauth/google` + `GoogleOAuthProvider`; agent domain + route group; `a_token` storage; `AgentProtectedRoute`/`AgentLayout`; `AgentLogin`, `AgentOnboarding`, placeholder `AgentHome`; agent auth service fns.
- **Out of scope:** the agent portal's real content — campaign list filtered by `visible_to_agents` + per-campaign referral links (SP5); agent referral earnings/reporting; password login for agents; admin agent-management UI.

## 4. Backend — `RenoXpert-Backend`

- **Migration (managed `users` table):** add `onboarded_at` nullable timestamp.
- **`UserResource`:** expose `onboarded_at`.
- **Config:** `config/services.php` → `'google' => ['client_id' => env('GOOGLE_CLIENT_ID')]`; add `GOOGLE_CLIENT_ID=` to `.env` (real value set by the user).
- **`AgentAuthController` (new, extends `BaseController`):**
  - `googleLogin(Request $request)` — public. Body `credential` (required string = Google ID token). Verify: `GET https://oauth2.googleapis.com/tokeninfo?id_token={credential}` via the existing Guzzle `Client`; on non-200 → 401. Parse JSON; require `aud === config('services.google.client_id')` and `email_verified` truthy (string 'true' or bool); else 401. Extract `email`, `name`.
    - `User::where('email', $email)->first()`:
      - exists & `type === 'agent'` → that user.
      - exists & `type !== 'agent'` → `sendError('This email is already in use.', [], 422)`.
      - none → create `User` with `name`, `email`, `type='agent'`, `status='active'`, `password = null` (referral_code auto-generated by the SP1 `creating` hook).
    - Issue `$user->createToken('AgentSite')->plainTextToken`.
    - Return `sendResponse(['token' => $token, 'user' => new UserResource($user), 'needs_onboarding' => is_null($user->onboarded_at)], 'Logged in.')`.
  - `onboarding(Request $request)` — `auth:sanctum`. Guard: `if ($request->user()->type !== 'agent') return sendError('Forbidden.', [], 403);`. Validate `{ name: 'nullable|string|max:255', country_code: 'required|string|max:8', phone_no: 'required|string|max:32', agree_terms: 'accepted' }`. Update the authed user's `name` (if provided), `country_code`, `phone_no`; set `onboarded_at = now()`; save. Return `sendResponse(new UserResource($user), 'Onboarding complete.')`.
- **Routes** (`routes/api.php`): `POST /agent/google-login → AgentAuthController@googleLogin` (public, near the other public auth routes); `POST /agent/onboarding → AgentAuthController@onboarding` (inside the `auth:sanctum` group).

## 5. Frontend — `RenoXpert-Frontend-v2.1`

- **Deps/env:** add `@react-oauth/google`; `.env`: `VITE_GOOGLE_CLIENT_ID=` (set by user) + `VITE_AGENT_URL=https://agent.renoxpert.my/` and `VITE_STAGING_AGENT_URL=https://s-agent.renoxpert.my/`.
- **Provider:** wrap the app (in `src/main.tsx` or App root) with `<GoogleOAuthProvider clientId={import.meta.env.VITE_GOOGLE_CLIENT_ID}>`. (Wrapping globally is fine; only the agent login uses it.)
- **Domain routing (`src/App.tsx`):** add `isAgentDomain` (`agent.renoxpert.my` / `s-agent.renoxpert.my` / `localhost`) and a new agent route group (e.g. `routeCat[7]`): `/login` (AgentLogin, `layout: null`), `/onboarding` (AgentOnboarding, gated), `/` (AgentHome, gated). Mirror the existing per-domain selection.
- **Auth gating:** `a_token` in `localStorage`. `AgentProtectedRoute` (redirects to `/login` if no `a_token`); after auth, if the loaded agent has `onboarded_at == null` route to `/onboarding`. A minimal `AgentLayout`.
- **Services** (`src/services/agentApi.ts` or in `auth.ts`): `agentGoogleLogin(credential)` → `POST agent/google-login`, stores `a_token` + returns `{ user, needs_onboarding }`; `agentOnboarding(payload)` → `POST agent/onboarding` with the `a_token` header; a `getAgentAuthHeaders()` helper reading `a_token`.
- **Pages:**
  - `AgentLogin` — branded page with the Google sign-in button (`useGoogleLogin`/`GoogleLogin` from `@react-oauth/google`); on credential → `agentGoogleLogin` → if `needs_onboarding` go `/onboarding` else `/`; error toast on failure (incl. the 422 email-clash).
  - `AgentOnboarding` — form: name (prefilled from the logged-in agent), `country_code` + `phone_no` (numeric), a required T&C checkbox; submit → `agentOnboarding` → `/`. Block direct access if already onboarded (redirect `/`).
  - `AgentHome` — placeholder authenticated landing ("Welcome, {name}") + a sign-out; **SP5 replaces the body with the campaign list**.

## 6. Constraints

- **No new backend dependency** (Google verify via existing Guzzle). One new **frontend** dep: `@react-oauth/google`.
- `users` is migration-managed (normal migration). **NEVER run `php artisan migrate`** (user runs it). `php` CLI unavailable → BE manual review. New controller uses `BaseController` helpers + `auth:sanctum`.
- Both repos deploy from **`production`**: backend **PR to `production`**, frontend **merge+push**.
- **FE gate:** `npm run build` exit 0 + scoped eslint no new errors; new files clean; no `any`. No test runner.
- **User infra (out of our control):** a Google OAuth **Web client** (authorized JS origins for the agent domain(s) + `http://localhost:5173`), its client id in `VITE_GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_ID`; DNS for `agent.renoxpert.my`. Until set, the Google button won't authenticate (graceful: shows an error), but the build/app still run.

## 7. Verification

- **Backend:** manual review — migration additive nullable timestamp; `UserResource` exposes it; tokeninfo verification checks `aud` + `email_verified` and 401s otherwise; email-clash branch returns 422 for non-agents; agent created active with null password; onboarding guards `type==='agent'` + `agree_terms accepted` + sets `onboarded_at`; routes (public login / auth onboarding) correct; uses `BaseController`.
- **Frontend:** build exit 0; eslint clean; no `any`.
- **Manual QA (after migrate + deploy + Google client configured):** first Google sign-in creates an agent and routes to onboarding; completing onboarding sets `onboarded_at` and lands on the placeholder home; a returning agent skips onboarding; signing in with a staff/owner email is rejected with a clear message; visiting agent routes without `a_token` redirects to `/login`.

## 8. Risks & mitigations

- **Token verification correctness** → verify `aud` against our client id AND `email_verified`; reject on any non-200/mismatch (prevents accepting tokens minted for another app).
- **Email clash / privilege confusion** → non-agent email is rejected (never converts a staff/owner into an agent).
- **Passwordless users** → `password` is nullable; agents never use password login (Google only).
- **Onboarding bypass** → `AgentProtectedRoute` routes un-onboarded agents to `/onboarding`; the home checks too.
- **Generic `auth:sanctum`** (no per-type guard) → the onboarding endpoint explicitly checks `type==='agent'` (403 otherwise); SP5's agent endpoints will do the same.
- **Google client not yet configured** → app builds and runs; the login button surfaces an error rather than crashing.

## 9. Non-goals

No agent password login; no email verification flow (Google already verifies); no `google_id` column (match by email); no admin agent-management/approval UI (open signup); no portal content (SP5); no agent referral dashboard/earnings.
